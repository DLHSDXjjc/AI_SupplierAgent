## 参数传递路径汇总

| 阶段 | 参数 | 从哪里来 | 传给谁 |
|------|------|---------|--------|
| 1 | `query` | 用户输入框 | app.py → HTTP POST /ask → rag_api |
| 2 | `query` | HTTP请求体 | agent.chat(query) → invoke({"input": query}) |
| 3 | `sku_id` | **LLM 推理出来的** | 从 Action Input 传给 inventory_query(sku_id) |
| 4 | `current_stock` 等 | **LLM 从第1轮 Observation 提取的** | 从 Action Input 传给 reorder_calculator(...) |

**关键点**：LLM 不是硬编码知道要传什么参数的——它从 @tool 的 docstring 里读到参数描述，从上一轮的 Observation 里提取参数值，自己拼出 Action Input。

## 启动 vs 请求：什么时候做什么事

| 时机 | 做什么 | 执行次数 |
|------|--------|---------|
| **启动时** | 加载 LLM、注册工具、创建 Agent、填 Prompt | **1次** |
| **启动时** | `partial(system_prompt=...)` 填人设 | **1次** |
| **启动时** | `create_react_agent()` 填 `{tools}` `{tool_names}` | **1次** |
| **每次请求** | `invoke({"input": query})` 填 `{input}` | **每次** |
| **每轮推理** | AgentExecutor 自动填 `{agent_scratchpad}` | **每轮** |

**关键点**：重量级操作（加载模型、注册工具）只在启动时做一次，每次用户请求只是调 `invoke()` 填 `{input}`，轻量快速。
